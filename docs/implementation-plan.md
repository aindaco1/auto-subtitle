Build a small native app for Apple Silicon on **macOS 15.0 or later**. Its primary job is to align an existing subtitle file with a video while preserving the subtitle wording and language, including translated subtitles. A separate mode generates subtitles in the spoken language. Both use one local processing pipeline.

**Confirmed product decisions**

| Area | Version 1 behavior |
|---|---|
| Align subtitles | Drop one video and one SRT or ASS, in either order. Same-language and translated subtitles are both required in the first MVP. Automatically check constant early/late offsets and timing-rate mismatches first; escalate only when needed. Preserve wording and subtitle language. |
| Improve accuracy | An explicit option within Align, off by default. Permit conservative audio-supported wording corrections and recovery of missing speech only for subtitles in the audio language. Keep translated subtitles in timing-only mode in version 1. |
| Subtitle cleanup | Apply the shared [subtitle quality policy](subtitle-quality-policy.md): intelligent wrapping, supported cue subdivision, redundant-caption consolidation, reading-speed checks, and format validation. On by default, including translations; separate from wording correction. |
| Generate subtitles | Separate mode: drop a video, transcribe its selected audio track, and generate subtitles. |
| Export | SRT and ASS. Preserve existing ASS styling where supported; use a simple default style for newly generated ASS. |
| Privacy | All processing stays on the Mac. Network access is used for explicit model setup, official release checks/downloads and reviewed sanitized report submission, never media or transcript processing. |
| Interface | One window, one job at a time, automatic defaults, progress, Cancel, Save, and Reveal in Finder. |
| UI visual style | Follow Podcast Visualizer's verified Dust Wave palette and rounded native card treatment, with semantic colors shared across the app and system light/dark support. |
| App icon | Create an original subtitle/alignment symbol: horizontal caption bars settling against a shared guide, with a small automation/snap cue, using the same palette. Include the finished icon in the first packaged MVP. |
| Recognition backend | Parakeet first, with its 25 supported languages. The authorized recognition-quality follow-up adds optional local Whisper retries for suspicious generated passages. Timing-only input is not restricted to those 25 languages. |
| Deferred | Subtitle editor, timeline, speaker labeling, generating or correcting translations, video rendering/burn-in, batch queue, and cloud processing. Aligning an existing translation is included. |

The original follow-up scope choices were **Parakeet first; local Whisper later**, and **timing-only alignment of translated subtitles in the first MVP**. A subtitle/audio language difference is valid input and must not block Align or redirect the user to Generate. Align preserves the subtitle language; Generate and eligible wording corrections follow the selected audio language. These replace the earlier provisional same-language-only alignment recommendation. The subsequent request to address English intrusion authorizes the bounded optional Whisper repair below; Parakeet remains primary.

The main window has an **Align / Generate** switch. Align shows a video drop area, a subtitle drop area, and an **Improve accuracy** checkbox. Generate shows only the video area. Both share output format and the primary action. Keep **Clean up formatting** on by default, with an off switch under Options for imported files; generation always uses the shared formatting policy. Show Audio language (Auto by default) only when recognition or wording correction needs it; timing-only Align needs no language selection. Show an audio-track selector only when the file contains multiple audio tracks. For a known translation, disable wording correction with a short explanation while leaving Align and formatting cleanup available. If the relationship is unknown, resolve it only when the user requests wording correction or a lexical alignment pass. Model setup appears only when needed. Follow system light/dark appearance and use standard accessible controls.

The user's follow-up specifically requires inexpensive correction of uniform early/late offsets and timing authored against another playback rate, including 25↔30 fps examples. These are automatic parts of Align even when Improve accuracy is off. Improve accuracy remains the optional wording-correction pass. No user choice of alignment algorithm is required.

The subsequent cleanup requirement permits line rewrapping, supported cue subdivision, and consolidation of redundant repeated captions while retaining language and lexical content. This refines the original requirement to preserve every line break and cue unchanged. Strict timing-only structure preservation remains available by turning cleanup off. The [subtitle quality policy](subtitle-quality-policy.md) owns the researched defaults, duplicate safeguards, format rules, and acceptance cases; do not duplicate those rules in separate UI or CLI implementations.

**Implementation shape and DRY ownership**

Use **SwiftUI → one bundled Node job runner → RecordSpeech helper and bundled FFmpeg/FFprobe**. Use a small bundled Python/ffsubsync helper for coarse synchronization. All modes call the same audio preparation, recognition, matching, quality checks, and export services. Node preserves direct reuse of the existing JavaScript timed-text and model-management code; Swift owns presentation and native file access. Python remains limited to the existing synchronization dependency.

Proposed app-owned locations are `macos/` for the SwiftPM app, `engine/` for job orchestration and subtitle adapters, `speech-sidecar/` for the native speech adapter, and `resources/model-manifests/` for generated manifests. Generic timed-text and model-install code belongs in pinned shared dependencies. Add shared exports and migrate Podcast Visualizer's relevant imports in the same extraction change, with its tests, so this does not create two implementations. Do not import app-private files through sibling absolute paths at runtime or copy the whole Podcast Visualizer runtime.

Preserve the Python CLI during migration. First capture its useful behavior in regression fixtures; move applicable rules into the shared authority. The eventual CLI entry point delegates to the new runner. Do not maintain independent Python and JavaScript implementations of the new Align/Generate/Improve policies.

Jobs use a versioned JSON request/result contract and structured progress events. Store immutable input identity, selected audio stream, model/engine versions, settings, chunk results, and final output identity in app-private job storage. Keep audio language, subtitle language, and their relationship (same/different/unknown) separate; allow unknown language fields for timing-only work. Cache recognition by media content and audio-stream identity, model revision, decoding settings, and chunk policy. Changing export format or enabling Improve can reuse compatible recognition. Restart resumes completed verified chunks; Cancel terminates child processes and preserves completed checkpoints. Completed job caches have an explicit cleanup action and a bounded retention policy.

Cache decoded audio windows and speech-activity signals as well as ASR results. Reuse one speech-activity reference across offset/rate candidates rather than decoding the movie for each attempt. The job contract records the selected method, scale, offset, validation residuals, sampled ranges, and actual decoded/transcribed audio seconds. A timing-only success need not have a transcription artifact or a speech-model dependency.

**Inexpensive timing checks before transcription**

Use one shared transform, `outputTime = scale × inputTime + offset`, for both cue starts and ends. A constant delay uses `scale = 1`; timing-rate drift changes `scale`; some files require both. Keep the transform in the shared timing authority, apply it to the original document once, and round only at the final SRT millisecond or ASS centisecond export boundary.

| Observed behavior | First correction to test |
|---|---|
| Already synchronized | Identity transform; retain existing timing. |
| Equally early or late throughout | One positive or negative offset. |
| Error grows steadily through the film | One time scale plus an optional offset. |
| Error jumps at a scene/edit boundary | Treat regions separately; reject a single global transform. |
| Individual cues disagree or evidence is ambiguous | Recognize the affected windows; expand to detailed alignment only as needed. |

SRT stores elapsed timestamps, not a declared frame rate. A video encoded at 25 fps does not automatically require changing subtitles associated with a 30 fps file: frame-rate conversion can preserve playback duration. If the same frame sequence was actually timed at 30 fps and is now played at 25 fps, the corresponding elapsed times scale by `30/25 = 1.2`; a 5-minute timestamp becomes 6 minutes before adding any offset. The inverse case uses `25/30`. Determine the correction from observed synchronization, not the filename, nominal video FPS, or the last subtitle's end time. [SRT format description](https://www.loc.gov/preservation/digital/formats/fdd/fdd000569.shtml).

Begin with 6–8 short, speech-rich windows distributed across the beginning, middle, and end; benchmark roughly 30–45 seconds per window. Retain original media timestamps and a validity mask for unsampled intervals. Do not concatenate samples into an artificial timeline or score unsampled time as silence. Reuse ffsubsync's speech-activity/correlation machinery to propose offset and scale; reserve separate windows for validation. If samples are sparse or ambiguous, extend them or scan full-track speech activity before resorting to full-track recognition.

Fit offset-only and scale-plus-offset candidates, favoring the simpler correction when it explains the evidence equally well. Explicitly test `25/30`, `30/25`, and common 23.976/24/25/29.97/30 conversions, using exact fractional rates where appropriate. ffsubsync's upstream implementation exposes offset and scale results and supports sampled synchronization, but available ratios and quality limits must be checked against the chosen immutable dependency pin. Its default candidates/search bounds must not silently exclude 25↔30 or reject their approximately 17–20% rate difference. Keep a bounded candidate list and reuse the library's reference signal; do not write a second correlation engine. [FFsubsync usage](https://github.com/smacke/ffsubsync), [FFsubsync implementation](https://github.com/smacke/ffsubsync/blob/master/ffsubsync/ffsubsync.py).

Accept the inexpensive result only when independent speech-rich validation windows agree across the film, the best match is unambiguous, and no residual step/drift or invalid cue bounds remains. Calibrate numeric confidence/residual thresholds against the held-out fixtures below; correlation score alone is insufficient. Compare with unchanged timing so a good input is not needlessly altered. With Improve off, a passing result goes straight to export with no ASR or language check, including translated subtitles. With Improve on and same-language eligibility established, retain the timing result and continue the requested wording analysis. Ambiguous or discontinuous cases escalate with the measured reason, reusing existing audio and evidence. The completion summary can say **Shifted 2.4 seconds later**, **Corrected timing speed**, or **Aligned individual cues**; these are results, not extra UI settings.

**Translated subtitles are a first-MVP acceptance requirement**

Use the same speech-activity signal, offset/rate transform, lossless document, and export services for all timing-only input. For example, Spanish audio with English subtitles must export English subtitles with identical wording and supported styling. Do not replace translation text with Parakeet's Spanish transcript, compare English words directly with recognized Spanish words, or require a translation model.

For harder translated input, expand speech-activity coverage and estimate bounded piecewise timing corrections around independently supported scene boundaries. A translated cue can summarize, reorder within a spoken turn, or combine several spoken phrases. Therefore do not require one subtitle cue per spoken phrase, derive durations from character counts, or snap every cue to the nearest detected speech event. Preserve authored cue structure during alignment; apply only supported changes in the separately recorded cleanup pass. Treat song lyrics, on-screen text, sound descriptions, and deliberate dialogue overlaps separately from ordinary speech cues.

Recognition may optionally provide a timing-only speech reference when the audio is supported and activity detection is insufficient. Use that reference's speech intervals rather than lexical similarity across languages; retain the translation unchanged. If neither global nor bounded local evidence supports the mapping, keep affected cues unchanged and report uncertainty instead of manufacturing precise timing. The translated path must be useful on benchmarked offset/rate and local-discontinuity cases before the first alignment MVP is accepted; it cannot be deferred until generation or an optional Whisper backend ships.

**Processing behavior**

1. Probe the container and selected audio stream. Decode requested windows from only that audio to 16 kHz mono PCM; defer full-track extraction until needed. Preserve the mapping from extracted samples back to the video timeline, including nonzero audio starts; do not infer timing from nominal video frame rate. Avoid denoising or aggressive normalization by default.
2. Parse subtitles into stable cue identities plus a lossless source document. Keep original payloads separate from normalized matching text. Accept UTF-8/BOM and recognized UTF-16; report ambiguous legacy encoding instead of replacing characters. ASS parsing must honor its `Format:` fields, commas in dialogue, styles, comments, overrides, layers, and deliberate overlaps.
3. For Align, run the inexpensive timing checks above. Skip recognition when a validated timing-only result can be exported. If detailed alignment, Generate, or Improve needs recognition, process the necessary audio in bounded overlapping chunks with silence-aware boundaries. Start benchmarking 60-second chunks with 2-second context overlap; tune from evidence. Restore source-relative word/token times and remove only duplicate observations of the same audio at chunk joins. The shared chunk planner needs a PCM/local-file policy and word-timing merge support instead of its current MP3/server assumptions. FFsubsync supplies speech-pattern synchronization, not a full arbitrary-text forced aligner.
4. When detailed alignment is needed, choose evidence appropriate to the input: confirmed same-language text may use normalized phrase matching against recognized words; translated or unknown-language text uses speech-activity and bounded piecewise timing evidence as described above. Reuse the accepted coarse transform and align locally within supported regions. Handle omissions, repeated phrases, and scene cuts explicitly. Parakeet timestamps locate its recognized words; they do not prove that the supplied subtitle text was forced-aligned. Never assign evenly spaced word timestamps to unmatched text. Expand from uncertain windows to full-film recognition only when the evidence requires it and the audio language is supported.
5. With Improve off, the alignment stage changes supported timing fields while retaining source wording, language, identities, and presentation. The shared cleanup stage may subsequently rewrap, split supported cues, or consolidate redundant identical events under the quality policy, retaining lineage. With cleanup off, preserve original cue structure and payloads exactly. Unmatched cues retain original timing, or a separately identified reliable coarse transform, and appear as unresolved in the report. Do not extrapolate through long unmatched spans or force an entire different film cut into one offset. If the result is substantially unresolved, say so before saving; do not call it fully aligned.
6. With Improve on, first require same-language eligibility. A known translation remains timing-only; explain that translated-wording correction is outside version 1 and never switch its language automatically. For eligible input, rerun only uncertain speech windows with additional context, evaluate token evidence and agreement, and apply conservative supported replacements/insertions. Confidence scores alone are not proof of correctness; repeated recognition can repeat an error. Preserve names, dialect, sound descriptions, and uncertain source text when evidence is weak. Keep original and changed text plus reasons in a local change report. No free-form LLM rewrite is required for version 1.
7. Generate uses the same recognized words to create readable cues at punctuation and acoustic pauses through the shared subtitle quality policy. Reflow must use observed word timing. Do not remove spoken fillers just because Podcast Visualizer suppresses them visually; consolidate only eligible redundant observations/display events, preserving meaningful repeated dialogue. Silence should not become invented captions.
8. Apply the shared formatting/cleanup policy to eligible exports, then validate display timing, content preservation and duplicate lineage, operation-specific language policy, and format round trips. Write a new output atomically. Align's language suffix follows the supplied subtitle language when known; otherwise preserve its original filename suffix or omit a new language code. Generate/Improve use the validated audio language. Spanish audio with English subtitles can therefore produce `movie.aligned.en.srt`; generation from that audio can produce `movie.generated.es.srt`. Never overwrite the source or an earlier result silently. A concise completion summary reports timing changes, rewrapping, splits, merges, and unresolved cues; an optional report contains details without adding an editor.

ASS alignment should patch Start/End fields in the original document. Preserve ordinary styling, positions, margins, and overrides; cleanup may restructure only events whose markup can be mapped safely, as specified in the shared quality policy. Karaoke and timed animation tags need special handling when cue duration changes: preserve safe uniform shifts, otherwise keep the affected event unchanged and report the limitation. Improve may edit styled text only when its markup can be mapped safely. ASS-to-SRT export necessarily loses ASS-only styling; state that at format selection. Newly generated ASS uses one default style. Do not route round trips through Podcast Visualizer's visual-renderer ASS exporter.
